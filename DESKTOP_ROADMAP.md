# Pixel Editor — desktop roadmap

План развития Electron/Windows-версии. Браузерные функции сюда не входят.

## Принципы

- Сохранять существующий формат проектов и обратную совместимость.
- Каждую фазу завершать проверками на Windows 10/11.
- Не добавлять функции, которые блокируют запуск или сохранение проекта.
- Все операции с файлами выполнять через безопасный валидируемый IPC.

## Этап 0. Базовая стабилизация

- [x] Исправить загрузку production-ресурсов Electron через `file://`.
- [x] Ограничить IPC сохранения типами, расширениями и размером файла.
- [x] Добавить обработчики ошибок `loadFile`, `loadURL` и renderer-crash.
- [x] Добавить диагностическое окно с понятным сообщением при сбое запуска.
- [ ] Добавить smoke-тест установленного приложения.

Критерий готовности: приложение запускается из установленной и portable-сборки, а ошибка запуска не приводит к немому чёрному окну.

## Этап 1. Нативное окно и меню

- [x] Добавить нативное меню: Файл, Правка, Вид, Холст, Окно, Справка.
- [x] Подключить команды меню к существующим действиям редактора.
- [x] Добавить полноэкранный режим.
- [x] Добавить режим скрытия панелей.
- [x] Показывать имя проекта в заголовке окна.
- [x] Показывать маркер несохранённых изменений.
- [x] Запоминать размер, позицию, состояние максимизации и масштаб окна.
- [ ] Безопасно восстанавливать состояние, если монитор или разрешение изменились.

Критерий готовности: пользователь может управлять приложением через меню и возвращается к последнему рабочему состоянию.

## Этап 5. Безопасность Electron

- [x] Добавить Content Security Policy для production-сборки.
- [x] Ограничить внешние URL для `shell.openExternal` протоколом HTTPS без credentials.
- [x] Отключить DevTools в production-сборке.
- [x] Проверить все IPC-каналы на проверку отправителя и входных данных.
- [x] Проверить импорт файлов на DoS через размеры и декодирование.
- [x] Добавить security-check для конфигурации Electron без содержимого проектов.
- [x] Проверить актуальность Electron `45.2.3` и Electron Builder `26.18.1`; обновление не требуется.
- [ ] Подписывать установщик и обновления сертификатом издателя.

Критерий готовности: security-review не выявляет доступ renderer к Node API, невалидируемых IPC-команд или неподписанных production-артефактов.

- [ ] `npm audit --omit=dev` и проверка production-артефактов.
- [ ] Ручная проверка установщика и portable-сборки.

## Порядок выполнения

1. Этап 0 — стабилизация запуска.
2. Этап 1 — нативное окно и меню.
3. Этап 2 — файлы и интеграция Windows.
4. Этап 3 — завершение заметок.
5. Этап 4 — производительность.
6. Этап 5 — security hardening.
7. Этап 6 — установка и обновления.
8. Этап 7 — финальная Windows-проверка.

Каждый этап выполняется отдельным изменением с тестами и обновлением этого файла.
