# Pixel Editor — desktop roadmap

План развития Electron/Windows-версии. Браузерные функции сюда не входят.

## Принципы

- Сохранять существующий формат проектов и обратную совместимость.
- Каждую фазу завершать проверками на Windows 10/11.
- Не добавлять функции, которые блокируют запуск или сохранение проекта.
- Все операции с файлами выполнять через безопасный валидируемый IPC.

## Этап 0. Базовая стабилизация

- [x] Исправить загрузку production-ресурсов Electron через `file://`.
- [x] Ограничить IPC сохранения типами, расширениями и размером файла.
- [x] Добавить обработчики ошибок `loadFile`, `loadURL` и renderer-crash.
- [x] Добавить диагностическое окно с понятным сообщением при сбое запуска.
- [x] Добавить smoke-тест собранного приложения: `win-unpacked` и portable.

Критерий готовности: собранные `win-unpacked` и portable-приложения запускаются с production-ресурсами через `file://`; ошибка запуска не приводит к немому чёрному окну. Запуск после установки NSIS отдельно проверяется на Этапе 7.

## Этап 1. Нативное окно и меню

- [x] Добавить меню приложения в renderer: Файл, Правка, Вид, Холст, Слой, Кадр, Анимация, Инструменты, Окно.
- [x] Подключить команды меню приложения к действиям редактора.
- [x] Добавить нативное меню Electron.
- [x] Добавить полноэкранный режим Electron.
- [x] Добавить режим скрытия панелей и сохранение раскладки рабочего пространства.
- [x] Показывать имя открытого файла в заголовке окна.
- [x] Показывать маркер несохранённых изменений в заголовке окна.
- [x] Запоминать размер, позицию и состояние окна.
- [x] Безопасно восстанавливать состояние, если монитор или разрешение изменились.

Примечание: нативное меню содержит основные команды редактора и переключатель полноэкранного режима; полный список динамических команд доступен через поиск команд в renderer. Заголовок окна показывает имя проекта и маркер изменений, а размер, позиция и максимизация восстанавливаются с коррекцией под доступные мониторы.

Критерий готовности: пользователь может управлять приложением через нативное меню и поиск команд и возвращается к последнему рабочему состоянию окна.

- [x] Зарегистрировать ассоциации файлов проекта `.pxproj` и оставить `.json` для совместимости.
- [x] Добавить пункт «Открыть в Pixel Editor» в контекстное меню Windows.
- [x] Обработать путь файла, переданный при запуске приложения или повторном запуске.
- [x] Поддержать drag-and-drop файлов проекта и изображений в окно Electron.
- [x] Добавить список последних проектов.
- [x] Открывать проект и экспортировать изображение через меню приложения; сохранение проекта использует системный диалог.
- [x] Реализовать «Сохранить как…» и отдельное подтверждение закрытия без сохранения.
- [x] Добавить предупреждение при закрытии изменённого проекта с вариантами «Сохранить», «Не сохранять» и «Отмена».
- [x] Добавлять до трёх резервных копий перед перезаписью в скрытую папку `.pixel-editor-backups` рядом с проектом.
- [x] Предлагать восстановление из последней резервной копии при повреждении проекта.
- [x] Добавить пакетный экспорт холстов в PNG в выбранную папку.

Критерий готовности: проект открывается из проводника, аргумента запуска, списка недавних проектов или перетаскиванием в окно; его можно сохранить, восстановить из резервной копии с подтверждением и экспортировать все холсты в выбранную папку. Реализованы ассоциация `.pxproj`, контекстный пункт Windows, IPC с проверками отправителя и параметров, лимиты пакетного экспорта и E2E-проверки основных потоков. Проверка реальной установки NSIS и активации ассоциации из Проводника остаётся ручным релизным тестом.

Поиск выделяет выбранное совпадение в редакторе, PDF формируется в Electron и сохраняется через системный диалог.

- [ ] Ограничить внешние URL для `shell.openExternal` протоколом HTTPS без credentials.
- [ ] Явно отключить DevTools в production-сборке.
- [x] Проверить все IPC-каналы на проверку отправителя и входных данных.

Критерий готовности: Electron security-проверки проходят на текущей конфигурации, а production-артефакты подписаны перед публичным распространением.

## Порядок выполнения

1. Этап 0 — стабилизация запуска.
2. Этап 1 — нативное окно и меню.
3. Этап 2 — файлы и интеграция Windows.
4. Этап 3 — завершение заметок.
5. Этап 4 — производительность.
6. Этап 5 — security hardening.
7. Этап 6 — установка и обновления.
8. Этап 7 — финальная Windows-проверка.

Каждый этап выполняется отдельным изменением с тестами и обновлением этого файла.
