# Pixel Editor

Настольный редактор пиксель-арта для Windows на Electron. Интерфейс работает внутри Electron на Vite + Svelte 5 + TypeScript и Canvas 2D; отдельной браузерной версии нет.
Ядро (`src/core`) написано на чистом TypeScript; интерфейс лежит в `src/components`.

## Запуск

Нужен Node.js 22 или новее; CI использует Node.js 22.

```bash
npm install
npm run dev         # запускает приложение Electron в режиме разработки
```

`npm run dev` запускает локальный Vite-сервер и Electron вместе; конвертировать проект в `.exe` для разработки не нужно. Оставьте терминал открытым, а для остановки нажмите `Ctrl+C`. `npm run desktop:dev` — синоним этой команды.

На Windows команда `npm run dist:win` проверяет типы и тесты, собирает интерфейс для Electron и выпускает установщик NSIS и portable `.exe` в `release/`. Она нужна только для распространения приложения. Установщик позволяет выбрать папку, создаёт ярлыки в меню «Пуск» и на рабочем столе; portable-версия запускается без установки. Открытие и сохранение файлов используют системные диалоги. Сборка не подписана сертификатом издателя, поэтому Windows SmartScreen может показать предупреждение; для публичного распространения потребуется code-signing certificate.

| Команда | Что делает |
|---|---|
| `npm run dev` | Запуск приложения Electron для разработки без сборки `.exe` |
| `npm run desktop:dev` | Синоним `npm run dev` |
| `npm run build:renderer` | Внутренняя сборка интерфейса для Electron в `dist/` |
| `npm run dist:win` | Проверенная сборка Windows NSIS installer и portable `.exe` в `release/` |
| `npm test` | Все тесты (ядро и интерфейс в jsdom) |
| `npm run check:e2e` | Проверка типов desktop E2E-сценариев |
| `npm run test:e2e:desktop` | Сквозные сценарии Electron desktop |
| `npm run test:watch` | Тесты в режиме наблюдения |
| `npm run check` | Проверка типов и a11y-подсказок Svelte |
| `npm run bench` | Замер CPU-части конвейера рисования |
| `npm run bench:render` | Базовые замеры Canvas 2D, слоёв, нескольких холстов и анимации |

`npm run bench:render` запускает отдельный Electron-сценарий и печатает JSON с окружением и замерами. Он проверяет типичный проект 256×256 с 6 слоями, крупный 1024×1024 с 4 слоями, 4 холста 256×256 с 4 слоями каждый и анимацию 512×512 с 8 кадрами. Включены задержка открытия до первого вывода на Canvas, время синхронного `putImageData`, переключение видимости слоя и интервалы `requestAnimationFrame` при воспроизведении. Время `putImageData` не измеряет завершение композитинга GPU. Это базовые наблюдения для сравнения вручную; временных порогов и CI-проверок производительности нет. Запускайте повторно на том же устройстве и в том же режиме питания, чтобы сравнения были полезны.

## Возможности

- Встроенные размеры 8/16/32/64/128/256/512/1024 или свой размер: до 4096 пикселей по стороне и до 4 194 304 пикселей по площади (смена размера с подтверждением и **с возможностью отмены**).
- Холст по умолчанию белый, а цвет рабочего пространства остаётся тёмным; оба цвета можно настраивать независимо.
- Пользовательские размеры холста (до 16 пресетов) сохраняются в настройках приложения; встроенные размеры: 8×8, 16×16, 32×32, 64×64, 128×128, 256×256, 512×512 и 1024×1024.
- Отдельная настройка цвета холста (за прозрачными пикселями) и окружающего рабочего пространства во вкладке «Фон» настроек. Фон холста используется для JPEG; PNG сохраняет прозрачность.
- Тёмная тема по умолчанию, системная и светлая темы в настройках; выбор сохраняется в приложении.
- Открытие и сохранение проектов, изображений и вспомогательных файлов через системные диалоги.
- Очистка холста с подтверждением и возможностью отмены через историю.
- Инструменты: карандаш, ластик, заливка, пипетка, линии, прямоугольники, окружности, эллипсы, треугольники, многоугольники, градиент и дизеринг; фигуры собраны в раскрывающуюся группу слева. Размер кисти (1–64 px) настраивается в выдвижных панелях карандаша и ластика; форма, непрозрачность и параметры текстур доступны в Brush Settings. Давление пера управляет размером кисти.
- Заметки проекта можно импортировать из TXT, Markdown и JSON, редактировать и экспортировать отдельно; заметки включены в файл проекта и автосохранение.
- Рабочее поле можно бесконечно перемещать правой кнопкой мыши; масштабирование колесом удерживает точку под курсором на месте.
- Непрерывная заливка использует обход горизонтальных сегментов и однобитную карту посещения вместо очереди размером со весь холст; поиск выполняется в Web Worker, а пакетное применение PixelBuffer передаёт управление основному потоку.
- Настройки отображения «Привязка», «Шахматный фон», «Повтор» и «Симметрия X/Y» собраны в компактной вкладке «Вид» верхней панели.
- Растровые слои: создание, дублирование, удаление, переименование и перестановка; независимое рисование, видимость, блокировка, миниатюры, непрозрачность, Normal/Multiply/Screen/Overlay/Add, Alpha Lock и Clipping Mask. Поддерживаются группы и вложенные группы с собственными видимостью, блокировкой, непрозрачностью, режимом наложения и цветовыми эффектами; слой можно переместить в любую группу. Роли «Фон» и «Референс» создают фиксированный нижний белый слой и неэкспортируемую копию текущей композиции соответственно. Яркость, контраст и насыщенность слоя или группы применяются неразрушающе. Заливка, пипетка и инструменты выделения могут брать образец с композиции видимых слоёв, продолжая изменять активный слой. Изменения пикселей, параметров и структуры входят в Undo/Redo; версии 5–9 добавляют слои/группы, референсы, эффекты слоя, Tilemap и кадры анимации; версии 1–12 открываются.
- Эффекты слоя (Этап 8): обводка, тень, свечение, карта градиента, сдвиг оттенка, яркость, контраст, постеризация, тонирование, шум, пикселизация, размытие и резкость. Эффекты применяются в указанном порядке; параметры, включение и удаление доступны в панели слоёв. Исходные пиксели не изменяются; стеки сохраняются в версии 7 проекта и поддерживают Undo/Redo.
- Tilemap Editor (Этап 9): извлечение tileset из активного холста, выбор и размещение тайлов, пиксельное редактирование основным/дополнительным цветом, слои карты, прямоугольная заливка случайными вариантами, анимация тайлов, бесшовное превью, прямоугольная/изометрическая/гексагональная сетка, экспорт PNG-атласа и JSON-метаданных. Tilemap сохраняется в версии 8 проекта и восстанавливается из автосохранения. Все действия карты и штрихи редактора тайлов входят в Undo/Redo; история Tilemap ограничена 100 шагами и 64 МБ.
- Интерфейс (Этап 10): меню File/Edit/View/Image/Layer/Frame/Animation/Tools/Window/Help и рабочие пространства «Рисование», «Анимация», «Tileset» и «Минимальное». Левая панель содержит выбор инструментов и шестерёнку их параметров; выделение и операции с ним доступны в меню «Правка». Правая панель содержит вкладки Colors, Palette, Layers, Properties, Brush Settings, Reference, History, Navigator, Preview, Brush Library, Grid Settings и Export; нижний Timeline. Боковые панели и Timeline можно скрывать и изменять по размеру мышью или клавиатурой; выбранная раскладка сохраняется в приложении.
- Timeline анимации: кадры активного слоя можно добавлять, дублировать, удалять, переключать и настраивать их длительность; доступно циклическое воспроизведение. Кадры разных слоёв сохраняются в версии 9 проекта. Экспорт GIF/APNG/WebP-анимации не входит в текущую реализацию.
- Менеджер референсов (кнопка «Референсы»): до 32 изображений и 4 194 304 исходных пикселей суммарно; импорт PNG/JPEG/WebP/BMP, перемещение, масштаб, поворот, непрозрачность, блокировка и скрытие. Трансформации и состояние менеджера поддерживают Undo/Redo. Пипетка может брать цвет непосредственно с видимого референса. Референсы сохраняются отдельно от слоёв и холстов и по умолчанию исключены из экспорта PNG/JPEG/WebP; включить их можно отдельным флажком «Экспортировать референсы».
- Палитры Game Boy (4), PICO-8 (16), NES (54), EGA (16), Fantasy (32), Pastel (32) и Card Art (160). Можно создавать собственные палитры до 256 цветов каждая; файл проекта хранит до 16 пользовательских палитр. Card Art содержит 20 подписанных тональных рамп: кожи, металла и золота, ткани и кожи, леса и листвы, бирюзы, магического циана, сапфира, индиго и аметиста — от теней до бликов. Режим «Свободный цвет» снимает ограничение палитрой.
- Основной и дополнительный цвета, недавние цвета. Рисование дополнительным цветом через Shift+ЛКМ можно включить или выключить во вкладке «Фон» настроек.
- Отмена и повтор: до 500 шагов (не меньше 100 гарантированно), один штрих — один шаг; история небольших штрихов сохраняет только изменённые пиксели без полного снимка холста.
- Экспорт PNG с альфа-каналом в масштабе ×1, ×4, ×8, ×16 без сглаживания; безопасный лимит результата — 16 млн пикселей, недоступные масштабы отключаются автоматически.
- Импорт изображений PNG, JPEG/JPG, WebP и BMP в исходном разрешении и с сохранением пропорций; редактор подгоняет холст под изображение, не обрезая его и не уменьшая. Поддерживаются изображения до 4096 пикселей по стороне и до 4 194 304 пикселей по площади.
- Проект сохраняется в JSON и открывается из файла; автосохранение переживает перезапуск приложения. Версия 10 добавляет кисти и расширяемые метаданные, версия 11 — пользовательские палитры, версия 12 — заметки проекта; версии 1–11 остаются совместимыми.
- Проект сохраняет несколько холстов, слои и группы, cel-кадры, эффекты, встроенные и пользовательские палитры, цвета, референсы и Tilemap. Входящие кисти, палитры и метаданные проверяются до применения; метаданные можно редактировать в панели свойств.
- Автосохранение проекта хранится в IndexedDB с проверкой записи; fallback в localStorage также проверяет сохранённые данные. Старый autosave переносится в IndexedDB только после проверки, исходная копия сохраняется до подтверждения.
- Нативное меню Electron содержит основные команды редактора; полноэкранный режим переключается через меню «Вид» или F11. Заголовок окна показывает имя открытого проекта и маркер несохранённых изменений; размер, положение и максимизация окна восстанавливаются, даже если изменился монитор или разрешение.
- Мышь, перо, сенсорный экран и полное управление с клавиатуры. Адаптивная вёрстка от телефона до десктопа.

## Горячие клавиши

Клавиши привязаны к физическому положению (`KeyboardEvent.code`), поэтому работают на любой раскладке, в том числе русской. Сочетания и последовательности до трёх нажатий настраиваются в диалоге настроек; схема версии 1 при импорте мигрирует автоматически. Справка в приложении: **H** или **F1**.

| Клавиша | Действие |
|---|---|
| `P` / `E` / `B` / `I` / `L` / `R` | Карандаш / ластик / заливка / пипетка / линия / прямоугольник |
| `U` / `C` / `J` / `O` / `K` | Залитый прямоугольник / окружность / залитый круг / эллипс / залитый эллипс |
| `T` / `Y` / `N` / `M` | Треугольник / залитый треугольник / многоугольник / залитый многоугольник |
| `V` / `D` | Градиент / дизеринг |
| `1`–`9` | Размер кисти, px |
| `X` | Поменять основной и дополнительный цвета |
| `G` | Показать или скрыть сетку |
| `F` | Вписать холст в окно |
| `+` / `−` | Масштаб |
| `Пробел` + перетаскивание | Панорама (также средняя кнопка мыши и перетаскивание правой кнопкой) |
| `Ctrl+Z` | Отменить |
| `Ctrl+Shift+Z`, `Ctrl+Y` | Повторить |
| `Ctrl+S` | Сохранить проект в файл JSON |
| `Ctrl+C`, `Ctrl+X`, `Ctrl+V` | Копировать / вырезать / вставить выделение |
| `Ctrl+Shift+P` | Найти команду в редакторе |
| `H`, `F1` | Справка по клавишам |

На macOS вместо `Ctrl` работает `⌘`.

## Управление

**Мышь и перо.** ЛКМ рисует основным цветом. Если включить настройку во вкладке «Фон», Shift+ЛКМ рисует дополнительным цветом. Правый клик по холсту открывает меню действий; перетаскивание пустого пространства с зажатой ПКМ панорамирует рабочую область. Колесо меняет масштаб к точке под курсором. Размер, форму и непрозрачность кисти задавайте в панели инструментов; давление пера изменяет размер отпечатка. Удерживайте Alt для временной пипетки. Пипетка кладёт цвет в основной слот по ЛКМ и в дополнительный по ПКМ; при радиусе больше 1 усредняются цвет и альфа пикселей. Разворачиваемый блок «Форматы цвета» показывает HEX, RGB, RGBA и HSV для обоих цветовых слотов.

**Инструменты рисования.** Шестерёнка в левой панели открывает параметры выбранного инструмента: Pixel Perfect для карандаша, привязку угла линии, режим/допуск/связность и защиту альфа-канала заливки, радиус пипетки, число сторон многоугольника, линейный или радиальный градиент, прозрачный конец и средняя точка. Залитые фигуры используют дополнительный цвет внутри и основной для контура. Дизеринг поддерживает шахматный, Bayer, диагональный и пользовательский паттерны, плотность, масштаб и угол. Размер и форма кисти настраиваются во вкладке Brush Settings.

**Выделение и трансформации.** В меню «Правка» выбираются прямоугольная и эллиптическая области, свободное и многоугольное лассо, волшебная палочка (связная область по допуску), выбор всех пикселей заданного цвета и выбор непрозрачных пикселей. Там же задаются операции комбинирования масок и команды трансформации: копирование, вырезание, вставка, сдвиг, отражение, поворот, масштабирование и обрезка холста. Включите «Выделять и копировать по видимым слоям» во вкладке Properties, чтобы выбор цвета/непрозрачности, копирование и создание слоя из выделения использовали композицию видимых слоёв.

**Библиотека кистей.** Раздел «Кисти» позволяет создавать отпечатки из текущей формы, редактировать маску пиксель за пикселем (мышью или стрелками/Enter), менять размер и параметры (угол, интервал, плотность, разброс, случайные размер/поворот и давление), сохранять набор в приложении, импортировать или экспортировать JSON через системные диалоги. Поддерживаются квадратные, круглые, пользовательские, pattern, stamp, texture и scatter-кисти; набор ограничен 64 кистями и валидируется при импорте.

**Размер и фон.** В панели сверху задайте ширину и высоту от 1 до 4096; площадь холста ограничена 4 194 304 пикселями. Системные квадратные пресеты доступны от 8×8 до 1024×1024. Текущий пользовательский размер можно сохранить в списке «Мои размеры»; встроенные пресеты туда не добавляются. По умолчанию фон холста белый, а пространство вокруг него тёмное. Цвета настраиваются отдельно во вкладке «Фон» в разделе «Настройки» и хранятся в настройках приложения, отдельно от файла проекта. Там же включается рисование дополнительным цветом через Shift+ЛКМ. Фон холста применяется также при экспорте JPEG, а PNG сохраняет прозрачность. Правый клик по холсту открывает меню действий с командой удаления; последний холст удалить нельзя, а удаление можно отменить через Ctrl+Z. Перетаскивайте пустое пространство правой кнопкой или средней кнопкой мыши, чтобы перемещаться. Чтобы выбрать несколько холстов, нажимайте на них правой кнопкой мыши, удерживая Ctrl; перетаскивание выбранного холста перемещает всю группу, а перетаскивание невыбранного — только его. Горизонтальная полоса прокрутки всегда видна внизу рабочей области, а размер её бегунка не зависит от масштаба. Для детальных рисунков включите «Свободный цвет» в панели палитры. Кнопка «Очистить» спрашивает подтверждение; результат можно вернуть через Ctrl+Z.

**Файлы и оформление.** Стрелка слева в верхней панели открывает системный диалог выбора проекта или изображения и настройки экспорта (формат, масштаб и экспорт). Кнопка с шестерёнкой открывает «Настройки», где доступны системная тема, тёмная (по умолчанию) и светлая; выбор сохраняется в приложении. Системная тема автоматически следует за настройкой операционной системы. Сохранение проекта и экспорт открывают системный диалог выбора имени и места.

**Импорт и экспорт изображений.** «Открыть» принимает проекты JSON и изображения PNG, JPG/JPEG, WebP и BMP. Холст автоматически получает точные размеры изображения; оно не обрезается, не уменьшается и не квантуется выбранной палитрой. Поддерживаются холсты до 4096 пикселей по стороне и до 4 194 304 пикселей по площади. Для защиты от чрезмерного потребления памяти принимаются файлы до 32 МБ и декодированные изображения до 32 мегапикселей. Изображения больше допустимого размера явно отклоняются, а не изменяются молча. Перед заменой текущего рисунка показывается подтверждение. Экспорт через системный диалог поддерживает PNG (с прозрачностью, без потери пикселей), WebP (с прозрачностью) и JPEG (с потерями). Для JPEG прозрачные области заполняются выбранным однотонным фоном рабочей области. Масштаб ×1/×4/×8/×16 использует nearest-neighbor, чтобы сохранить чёткие края pixel art. Масштабы, дающие более 16 млн пикселей, блокируются до выделения памяти; выберите меньший масштаб.

**Автосохранение.** Проект сохраняется во внутреннем хранилище приложения на базе IndexedDB; после записи редактор проверяет, что может прочитать ту же версию проекта. Для восстановления старых данных поддерживается перенос autosave из localStorage. При ошибке хранилища показывается уведомление и рекомендуется сохранить проект в JSON через системный диалог.

**Сенсорный экран.** Один палец рисует. Второй палец включает жест: щипок меняет масштаб, перемещение двух пальцев двигает холст. Штрих, который успел начать первый палец, при этом отменяется целиком.

**Клавиатура.** Tab переводит фокус на холст. Дальше:

| Клавиша | Действие |
|---|---|
| `←` `↑` `→` `↓` | Двигать курсор на пиксель (с `Shift` — на 8) |
| `Enter` | Начать штрих; повторное нажатие заканчивает его. `Shift+Enter` — дополнительным цветом |
| `Escape` | Отменить текущий штрих целиком |

Заливка и пипетка срабатывают сразу по первому `Enter`. Все кнопки интерфейса доступны через Tab и имеют видимый фокус.

```json
{
  "format": "pixel-editor-project",
  "version": 12,
  "savedAt": "2026-11-04T10:00:00.000Z",
  "width": 32,
  "height": 32,
  "pixels": "<RGBA, base64, width × height × 4 байт>",
  "palette": { "id": "pico8", "freeColor": false },
  "colors": { "primary": [255, 0, 77, 255], "secondary": [255, 241, 232, 255] },
  "recent": [[255, 0, 77, 255]],
  "notes": "# Заметки проекта\n\nИдеи и сведения о проекте."
}
```

При открытии файл проверяется: JSON, маркер формата, версия (более новые не открываются), допустимые размеры холста, длина данных пикселей, слои, кадры, кисти, метаданные и заметки. Полностью прозрачные пиксели приводятся к `(0, 0, 0, 0)`. Тот же формат использует автосохранение (ключ `pixel-editor:autosave`). Если сохранение не удалось прочитать, его копия кладётся в `pixel-editor:autosave:unreadable`.

История Undo/Redo остаётся доступной в рамках текущей сессии при сохранении файла и автосохранении; при открытии другого проекта история начинается заново. История, выбранный инструмент, размер кисти, сетка и положение холста не входят в JSON-файл.

## Как это устроено

**Отрисовка.** `PixelBuffer` копит «грязный» прямоугольник: любая запись пикселя расширяет его. `PixelRenderer` раз в кадр (`requestAnimationFrame`) забирает этот прямоугольник и выводит на canvas только его одним вызовом `putImageData` с dirty-параметрами. `ImageData` делит память с буфером, копирования нет. Сотня событий указателя за кадр превращается в одну отрисовку. Масштаб и шахматный фон делает CSS (`image-rendering: pixelated`), сетка — CSS-градиент.

**Штрих.** `StrokeSession` — единственное место, где определено, что такое штрих: старт, движение (повторные позиции пропускаются), завершение, откат. Мышь, перо, касание и клавиатура ведут штрих одним и тем же кодом. Инструмент получает `begin / move / end / cancel` и сам соединяет точки по Брезенхэму, поэтому быстрые штрихи не рвутся.

**История.** Во время штриха исходные цвета запоминаются только для затронутых пикселей; в шаг истории попадает компактный diff (индекс и значения до/после — 12 байт на изменённый пиксель). Для плотных операций используется снимок, чтобы не создавать чрезмерно большую разреженную карту. Штрихи без видимых изменений в историю не попадают. Смена размера — отдельный шаг: хранятся только непрозрачные пиксели, которые обрезка уничтожила. Лимиты: 500 шагов и 64 МБ, но последние 100 шагов не выбрасываются никогда.

**Прозрачность.** Полностью прозрачный пиксель всегда хранится как `(0, 0, 0, 0)`. Иначе заливка и история видели бы разницу между пикселями, неотличимыми на экране.

**PNG.** Кодируется напрямую из буфера (`png.ts`), минуя canvas: canvas хранит пиксели с premultiplied-альфой и искажает цвета полупрозрачных пикселей. Сжатие — встроенный в Electron `CompressionStream`, при его отсутствии файл пишется без сжатия.

## Зависимости и безопасность

`npm audit --omit=dev` не находит уязвимостей в зависимостях приложения. Полный аудит находит низкий advisory (`GHSA-gcqx-w48m-w2h4`) для `deepmerge@4.3.1` через Svelte Vite plugin и умеренные advisory в `minimatch` через Electron Builder. Это только инструменты разработки/упаковки, не попадающие в установленное приложение. npm предлагает для Builder downgrade до `25.1.0`; мы сохраняем актуальную ветку `26.x`, а CI блокирует high/critical уязвимости и отдельно проверяет чистый production audit.

Плагин и `deepmerge` находятся в `devDependencies`; плагин подключён только в `vite.config.ts` для локального сервера и сборки. Код приложения не импортирует `deepmerge`, а проверка `npm audit --omit=dev` не находит уязвимостей. Не принудительно понижайте `deepmerge` за пределы диапазона, заявленного плагином: это может нарушить совместимость. После публикации исправления Dependabot должен предложить обновление зависимостей; после проверки обновления запустите `npm audit` и удалите эту заметку, если advisory закрыт.

Обновления npm-зависимостей проверяются еженедельно через Dependabot (`.github/dependabot.yml`). Эта настройка начнёт работать, когда проект будет опубликован в GitHub; для security alerts и PR также должны быть включены соответствующие настройки Dependabot в репозитории.

## Тесты

`npm test` запускает проверки инструментов (включая 2400 случайных штрихов на разрывы), заливки, истории, палитр и настроек, формата проекта и IndexedDB autosave/миграции, безопасного UTF-8-хранилища заметок, экспорта, PNG, отрисовки и UI-сценариев в jsdom. `npm run check` проверяет типы и Svelte-доступность.

Для сквозного теста Electron запустите `npm run test:e2e:desktop`. Playwright поднимает Vite и приложение Electron, затем проверяет импорт Markdown-заметок проекта. Устанавливать отдельный Chromium для этого сценария не нужно. Нативная упаковка проверяется отдельной Windows-задачей CI.

GitHub Actions использует Node.js 22. На push и pull request CI выполняет unit/component-тесты, проверки типов, сборку renderer и аудит зависимостей; Windows-задача запускает Electron E2E-тест и проверяет сборку приложения.

## Приветствие и заметки

При первом запуске показывается приветствие; подтверждение ознакомления сохраняется в пользовательских настройках. Открыть приветствие повторно можно кнопкой `i` слева от «Настроек». Создание, просмотр и редактирование заметок обратной связи доступны кнопкой «Заметки обратной связи» на верхней панели. Заметки хранятся вместе в UTF-8-файле `feedback-notes.txt` в пользовательском каталоге данных Electron. Записи имеют последовательные номера и даты создания/изменения; при повреждённом файле или ошибке записи исходные данные сохраняются, а приложение показывает ошибку. Эта функция требует настольную версию приложения.

## Известные ограничения

- jsdom и Chromium не заменяют проверку на реальном графическом планшете: давление пера, производительность на целевых устройствах и нативные системные диалоги пока не входят в автоматизированные тесты и требуют отдельной проверки.
- Холст ограничен 4 194 304 пикселями; изображения, превышающие этот лимит, нужно уменьшить перед импортом.
- Открытие проекта заменяет рисунок и очищает историю: файл не добавляется шагом отмены.
- Если встроенный в Electron Chromium не предоставляет `CompressionStream`, PNG остаётся корректным, но может иметь больший размер.
