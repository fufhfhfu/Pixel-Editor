# ЗАДАНИЕ: Превратить существующий Pixel Editor в профессиональный Pixel Art Studio

## 1. Роль и цель

Твоя задача — последовательно модернизировать существующий редактор пиксельной графики, превратив его в полноценный профессиональный Pixel Art Editor, ориентируясь по функциональности и качеству на Aseprite и Pixelorama.

Это не создание нового приложения с нуля. Необходимо развивать текущий проект, максимально сохраняя его существующую архитектуру, работающие функции, производительность и совместимость.

**Главный приоритет проекта — исключительно высокое качество базовых инструментов рисования.**

Программа должна стать удобным профессиональным инструментом для художников, которые создают Pixel Art, игровых персонажей, объекты, текстуры, спрайты и игровые ассеты.

Не ограничивайся созданием визуальных кнопок и панелей. Каждая добавленная функция должна иметь полноценную рабочую реализацию.

# 3. Главный принцип разработки

Сохрани существующие технологии:

- Svelte 5.
- TypeScript.
- Vite.
- Canvas 2D.
- Electron.
- Vitest.
- Playwright.

Не переходи на другой технологический стек без объективной технической необходимости.

Сохрани разделение между чистым TypeScript-ядром и пользовательским интерфейсом.

Логику рисования, геометрии, выделения, преобразования изображений и обработки пикселей размещай в src/core.

Svelte используй для интерфейса, управления состоянием и взаимодействия с пользователем.

Не помещай всю логику редактора в App.svelte.

Постепенно разделяй крупные модули на независимые компоненты, не допуская чрезмерной фрагментации.

Сохрани поддержку браузерной версии и Windows Electron-приложения.

# 4. ЭТАП №1. Модернизация Drawing Engine

Это самый важный этап.

Необходимо превратить существующую систему рисования в профессиональный механизм Pixel Art.

## 4.1. Pencil

Расширить существующий карандаш.

Реализовать:

- Размер кисти от 1 до 64 пикселей с возможностью дальнейшего расширения.
- Квадратную форму кисти.
- Круглую форму кисти.
- Пользовательские формы кистей.
- Непрерывное рисование.
- Непрозрачность.
- Работу с основным и дополнительным цветом.
- Pixel Perfect.
- Предпросмотр кисти под курсором.
- Корректную работу с графическим планшетом.
- Поддержку давления пера.
- Стабильное рисование при быстром движении курсора.
- Рисование с клавиатуры.

Требования к качеству:

- Отсутствие пропусков между событиями указателя.
- Предсказуемая геометрия линий.
- Правильное расположение кисти относительно курсора.
- Отсутствие размытия.
- Отсутствие случайных изменений пикселей.
- Одинаковый результат при одинаковой траектории.

Сохрани алгоритм Брезенхэма, если он подходит для конкретной операции. При необходимости расширяй существующие алгоритмы, а не заменяй их без тестирования.

Пользователь должен иметь возможность создавать, редактировать, сохранять, импортировать и экспортировать собственные кисти.

Реализовать отдельный алгоритм Pixel Perfect.

Он должен обнаруживать нежелательные одиночные пиксели в характерных местах пересечения диагональных линий.

Режим должен включаться и отключаться пользователем.

Обязательно создать тесты на сложные пересечения линий, углы и диагональные формы.
